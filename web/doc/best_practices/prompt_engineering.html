提示词工程¶

OpenAI 官方文档：Prompt Engineering

运用提示工程策略增强结果。

本指南分享了一些策略和方法，用于从大型语言模型（有时称为GPT模型）如GPT-4o中获得更好的结果。这里描述的方法有时可以组合使用以获得更理想的效果。我们鼓励大家进行实验以找出最适合您的方法。

您还可以探索示例提示，展示我们模型的能力：

  • 提示示例

六种获取更好结果的策略¶

撰写清晰的指令¶

这些模型不能读心术。如果输出太长，要求简短回复。如果输出太简单，要求专家级的写作。如果您不喜欢格式，请展示您想要的格式。模型越少需要猜测您的需求，您越有可能得到满意的结果。

战术：

  • 在查询中包含细节以获得更相关的答案

  • 要求模型采用特定角色

  • 使用分隔符清晰标明输入的不同部分

  • 指明完成任务所需的步骤

  • 提供示例

  • 指定输出的期望长度

提供参考文本¶

语言模型可能会自信地编造错误答案，尤其是在被问及偏僻主题或引用和URL时。就像笔记可以帮助学生在考试中表现更好一样，向这些模型提供参考文本可以帮助减少不实之词。

战术：

  • 指导模型使用参考文本回答

  • 指导模型使用参考文本中的引用回答

将复杂任务分解为更简单的子任务¶

正如软件工程中将复杂系统分解为一组模块化组件是良好实践一样，将提交给语言模型的任务分解为更简单的任务也是如此。复杂任务的错误率通常较高。此外，复杂任务通常可以重新定义为较简单任务的工作流程，其中较早任务的输出用于构建后续任务的输入。

战术：

  • 使用意图分类来识别用户查询最相关的指令

  • 对于需要很长对话的对话应用，汇总或筛选以前的对话

  • 逐块汇总长文档并递归构建完整摘要

给模型时间“思考”¶

如果问17乘以28是多少，你可能不会立刻知道，但可以通过花时间计算出来。同样，模型试图迅速回答问题时会犯更多推理错误，而不是花时间推导出正确答案。要求在提供答案之前进行“思考链”可以帮助模型更可靠地推理出正确答案。

战术：

  • 指导模型先设法解决自己的方案再得出结论

  • 使用内在独白或一系列查询隐藏模型的推理过程

  • 询问模型是否在先前的尝试中遗漏了任何内容

使用外部工具¶

通过向模型提供其他工具的输出来补偿模型的不足。例如，一个文本检索系统（有时称为RAG或检索增强生成）可以告知模型有关相关文档的信息。像OpenAI的代码解释器这样的代码执行引擎可以帮助模型进行数学运算和运行代码。如果某个任务可以通过工具而不是语言模型更可靠或更高效地完成，请将其移交以获得最佳效果。

战术：

  • 使用基于嵌入的搜索实现高效的知识检索

  • 使用代码执行进行更准确的计算或调用外部API

  • 为模型提供对特定功能的访问

系统地测试更改¶

如果您可以衡量性能，提高性能更容易。在某些情况下，对提示的修改会在几个孤立的示例中获得更好的性能，但在更具代表性的一组示例中导致整体性能下降。因此，要确保某一变化对性能有净正面影响，可能需要定义一个全面的测试套件（也称为“评估”）。

战术：

  • 参考标准答案评估模型输出

策略¶

上述每个策略都可以通过具体战术实现。这些策略旨在提供尝试的思路。它们绝不是全面的，您应随意尝试这里未涉及的创意。

战术：对于需要很长对话的对话应用，汇总或筛选以前的对话¶

由于模型有固定的上下文长度，用户和助手之间的对话如果整个对话都包含在上下文窗口中，不能持续不间断。

此问题有各种解决方案之一是汇总对话中的先前回合。一旦输入大小达到预定的阈值长度，这可能触发一个查询，汇总部分对话，先前对话的汇总可作为系统消息的一部分提供。或者，在整场对话期间，先前的对话可以异步地在后台汇总。

一种替代解决方案是动态选择最相关于当前查询的先前对话部分。参见策略“使用基于嵌入的搜索实现高效的知识检索”。

战术：逐块汇总长文档并递归构建完整摘要¶

由于模型有固定的上下文长度，它们无法在单个查询中对比生成摘要更长的文本进行摘要。

要汇总很长的文档（如一本书），我们可以使用一系列查询对文档的每个部分进行汇总。这些部分摘要可以串连并汇总，产生总结摘要的摘要。此过程可以递归进行，直到整个文档被总结。如果有必要使用先前章节的信息来理解后续章节，那么一个有用的技巧是包含文本的运行摘要，该摘要在书中某点之前汇总，而在该点上总结内容。这种程序用于汇总书籍的有效性已在OpenAI的研究中得到探讨。

战术：使用内在独白或一系列查询隐藏模型的推理过程¶

上一战术展示有时重要的事是模型在回答特定问题前详细推理。对于一些应用程序来说，模型用来得出最终答案的推理过程不宜向用户展示。例如，在辅导应用中，我们可能希望鼓励学生自己解题，但模型对学生解答的推理可能向学生透露答案。

内在独白是可用来减轻此问题的策略。内在独白的思想是让模型用指定格式将意图隐藏给用户的输出部分写出，使其易于解析。然后在向用户展示输出之前，解析输出并仅显示部分输出。

SYSTEM

步骤2 - 将您自己的解决方案与学生的解决方案进行比较并评估学生的解决方案是否正确。将该步骤的所有工作用三重引号括起来（"""）。

步骤4 - 若学生有错误，提供上一步的提示给学生（不在三重引号内）。用"提示："代替"步骤4 - ..."。

战术：询问模型是否在先前的尝试中遗漏了任何内容¶

假设我们正在使用模型列出与特定问题相关的来源摘录。在列出每个摘录后，模型需要确定是否应开始写下一个或应停止。如果源文档较大，模型常过早停止未能列出所有相关摘录。在这种情况下，通过后续查询提示模型找出之前遗漏的摘录往往可以获得更好性能。

策略：使用外部工具¶

战术：使用基于嵌入的搜索实现高效的知识检索¶

如果作为输入提供模型，则模型可以利用外部信息来源。这可以帮助模型生成更加知情和最新的回复。例如，如果用户询问关于特定电影的问题，可能在模型输入中添加有关该电影的高质量信息（例如演员、导演等）很有用。

嵌入可以用于实现高效的知识检索，以便在运行时动态为模型输入添加相关信息。

文本嵌入是一种向量，可以度量文本字符串之间的相关性。相似或相关字符串将更加接近，而不相关的字符串则更为分离。利用这一事实以及快速向量搜索算法的存在意味着嵌入可以用于实现高效的知识检索。具体来说，可以将一个文本库分割成多个块，每个块嵌入并存储。然后可以将给定查询嵌入并执行向量搜索以找到与查询最相关的文本块（即在嵌入空间中最接近的）。

示例实施可以在OpenAI Cookbook中找到。有关如何使用知识检索最大限度减少模型出错可能性的示例，请参见策略“指导模型使用参考文本回答”。

战术：使用代码执行进行更准确的计算或调用外部API¶

语言模型无法仅凭自身准确进行算术或长计算。在需要这种情况下，可以指导模型编写和运行代码而不是进行自己的计算。特别地，可以指导模型将要运行的代码放入指定格式中，如三重反引号。生成输出后，可以提取代码并运行。最后，如有必要，可以将来自代码执行引擎（即Python解释器）的输出作为输入提供给模型以进行后续查询。

SYSTEM

您可以通过将Python代码用三重反引号括起来来编写和执行它，例如 ```代码在此输入```。用此来执行计算。

USER

寻找以下多项式的所有实值根：3*x**5 - 5*x**4 - 3*x**3 - 7*x - 10.。

使用代码执行的另一个良好用例是调用外部API。如果一个模型被指导正确使用API，它可以编写使用它的代码。可以通过提供文档和/或代码示例展示如何使用API来指导模型使用API。

SYSTEM

您可以通过将Python代码用三重反引号括起来编写和执行它。还注意您可访问以下模块帮助用户给朋友发送消息：
```python

警告：执行模型生成的代码固有地并不安全，任何着眼于进行此操作的应用需采取预防措施。特别地，需隔离执行环境以限制不可信代码可能造成的损害。

战术：为模型提供对特定功能的访问¶

Chat Completions API 允许在请求中传递函数描述列表。这使得模型可以根据提供的模式生成函数参数。生成的函数参数由API以JSON格式返回，并可用于执行函数调用。申明由函数调用提供的输出然后可在后续请求中反馈至模型以形成闭环。这是使用OpenAI模型调用外部函数的推荐方式。欲了解更多，请参阅我们文本生成指南入门的函数调用章节及更多函数调用示例（OpenAI Cookbook）。。

策略：系统地测试更改¶

有时很难判断某一变化如新指令或新设计是否使您的系统更好或更糟。查看几个示例或许能暗示哪一个更好，但样本量小时难以区分真正改善和运气随机。也许变化有助于某些输入表现，却损害其他表现。

评估程序（或“评估”）对优化系统设计用处很大。好的评估应：

  • 代表真实使用场景（或至少多样化）

战术：参考标准答案评估模型输出¶

假设已知某问题的正确答案应引用特定的已知事实集。那么我们可以使用模型查询来计算答案中包含了多少必要事实。

例如，使用以下系统消息:

- 尼尔·阿姆斯特朗是第一个登上月球的人。
- 阿姆斯特朗首次登上月球的日期是1969年7月21日。
对于每个点执行以下步骤：
1 - 重申该点。
2 - 提供答案中最接近该点的引用。
3 - 考虑一个不熟悉该主题的人是否会直接从引用中得出该点的结论。解释为什么或为什么不，然后再作出决定。
4 - 如果第3项回答为是则写"是",否则写"否"。
最后，提供"是"答案的数量作为{"count": <插入数量>}。
