OpenAI提示词缓存¶

OpenAI 官方文档：Prompt caching

先说结论¶

  • 对于 1024 个令牌或更长的提示，会自动启用缓存；

  • 缓存命中仅适用于提示词的精确前缀匹配，要实现缓存的优势，请将说明和示例等静态内容放在提示词的开头，将可变内容放在末尾。这也适用于图像和工具；

  • 返回值提供 cached_tokens 字段，指示缓存命中了多少提示令牌。对于 1024 个令牌以下的请求，cached_tokens 将为0；

  • 缓存有效期通常为5-10分钟，非高峰期可能会持续1小时；

概述¶

模型提示通常包含重复的内容，例如系统提示和常用指令。 OpenAI 将 API 请求路由到最近处理过相同提示的服务器，这使得它比从头开始处理提示更便宜、更快。对于长提示，这可以减少高达 80% 的延迟和 50% 的成本。提示缓存会自动处理您的所有 API 请求（无需更改代码），并且没有与之相关的额外费用。

如何构建可以缓存的提示词¶

缓存命中仅适用于提示中的精确前缀匹配。要实现缓存的优势，请将说明和示例等静态内容放在提示符的开头，并将可变内容（如用户特定信息）放在末尾。这也适用于图像和工具。

它是如何运作的¶

对于 1024 个令牌或更长的提示，会自动启用缓存。当您发出 API 请求时，会发生以下步骤：

  • 缓存查找：系统检查提示的初始部分（前缀）是否存储在缓存中。

  • 缓存命中：如果找到匹配的前缀，系统将使用缓存的结果。这显着减少了延迟并降低了成本。

  • 缓存未命中：如果没有找到匹配的前缀，系统将处理您的完整提示。处理后，提示的前缀将被缓存以供将来的请求使用。

缓存的前缀通常在不活动的 5 到 10 分钟内保持活动状态。但是，在非高峰时段，缓存可能会持续长达一小时。

要求¶

缓存可用于包含 1024 个或更多令牌的提示，缓存命中以 128 个令牌为增量发生。因此，请求中缓存的令牌数量将始终遵循以下顺序：1024、1152、1280、1408 等，具体取决于提示的长度。

所有请求（包括少于 1024 个令牌的请求）的返回值都将提供 cached_tokens 字段，指示缓存命中了多少提示令牌。对于 1024 个令牌以下的请求，cached_tokens 将为0。

"usage": {
  "prompt_tokens": 2006,
  "completion_tokens": 300,
  "total_tokens": 2306,
  "prompt_tokens_details": {
    "cached_tokens": 1920
  },
  "completion_tokens_details": {
    "reasoning_tokens": 0,
    "accepted_prediction_tokens": 0,
    "rejected_prediction_tokens": 0
  }
}

可以缓存什么¶

  • 消息：完整的消息数组，包括系统、用户和助理的消息内容；

  • 图像：用户消息中包含的图像（作为链接或作为 Base64 编码数据）以及可以发送多个图像。确保详细参数设置相同，因为它会影响图像标记化；

  • tools：消息数组和可用 tools 列表都可以缓存，从而满足最低 1024 个令牌要求；

  • 结构化输出：结构化输出模式充当系统消息的前缀，可以被缓存；

最佳实践¶

  • 结构提示开头为静态或重复内容，结尾为动态内容；

  • 监控缓存命中率、延迟和缓存令牌百分比等指标，以优化提示和缓存策略；

  • 要增加缓存命中率，请使用更长的提示并在非高峰时段发出 API 请求，因为高峰时段缓存驱逐会更加频繁；

  • 最近未使用的提示会自动从缓存中删除。为了最大程度地减少驱逐，请保持具有相同提示前缀的一致请求流；

常见问题¶

  1. 如何维护缓存的数据隐私？
    提示缓存不在组织之间共享。只有同一组织的成员才能访问相同提示的缓存。

  2. 提示缓存是否会影响输出令牌生成或 API 的最终响应？
    提示缓存不会影响输出令牌的生成或 API 提供的最终响应。无论是否使用缓存，生成的输出都将是相同的。这是因为仅缓存提示本身，而每次都会根据缓存的提示重新计算实际响应。

  3. 有没有办法手动清除缓存？
    目前无法手动清除缓存。最近没有遇到过的提示会自动从缓存中清除。典型的缓存驱逐发生在 5-10 分钟不活动后，但有时在非高峰时段最多持续一小时。

  4. 我需要为写入提示缓存支付额外费用吗？
    不会。缓存会自动发生，无需执行任何显式操作，也无需支付额外费用即可使用缓存功能。

  5. 缓存的提示是否会影响 TPM 速率限制？
    是的，因为缓存不会影响速率限制。

  6. 规模层和批处理 API 上是否可以享受提示缓存折扣？
    提示缓存折扣在 Batch API 上不可用，但在 Scale Tier 上可用。通过 Scale Tier，任何溢出到共享 API 的令牌也将有资格进行缓存。

  7. 提示缓存是否适用于零数据保留请求？
    是的，提示缓存符合现有的零数据保留策略。
